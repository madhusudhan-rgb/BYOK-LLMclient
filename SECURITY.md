# Security Policy

## Supported Versions

This project is actively developed, and security updates will generally be provided for the latest version.

| Version | Supported |
| ------- | --------- |
| Latest release | ✅ |
| Older releases | ⚠️ Limited support |
| Unreleased versions | ❌ |

---

# Reporting a Security Issue

If you discover a security vulnerability, please do **not** publicly disclose it through GitHub Issues.

Instead, report it privately by contacting the developer through the contact information provided in the repository.

Please include:

- A description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Any screenshots, logs, or proof-of-concept information (if applicable)

Reports will be reviewed as soon as possible.

---

# API Key Security

This project uses third-party APIs to provide AI functionality.

Users may configure their own API keys when using the open-source version.

Do not:

- Attempt to extract or abuse developer-provided API credentials.
- Share private API keys publicly.
- Use API keys outside their intended purpose.
- Attempt to bypass usage limits or security controls.

If abuse of developer-provided API resources is detected, access may be restricted or revoked.

---

# Data Security

The application may store user information such as:

- Account information
- User preferences
- Chat history (if enabled)

Reasonable measures are taken to protect stored information. However, no online service can guarantee complete security.

Users should avoid sharing sensitive personal information through AI conversations.

---

# Third-Party Services

This application relies on third-party services, which may include:

- AI model providers
- Authentication providers
- Database providers
- Hosting services

Security issues involving third-party services should also be reported to the respective provider.

---

# Open Source Security

Because this project is open source:

- Anyone may inspect the code.
- Anyone may suggest improvements.
- Anyone may report vulnerabilities.

However, modifying the application locally does not grant permission to misuse backend resources, developer-owned services, or API credentials.

---

# Responsible Disclosure

Security researchers and users are encouraged to responsibly disclose vulnerabilities.

Please allow reasonable time for investigation and fixes before publicly sharing security details.

Thank you for helping keep this project secure.
